IC / TO 是怎么算的、什么时候不该信

每只脚独立：整段取方差最大的原始陀螺轴，正负两个方向各算一遍 —— 对每个方向的门限以上正波瓣取峰作摆动锚 （同一个连续正波瓣里被门限劈开的多个峰先并成一个，再按峰高做 200 ms 抑制），再看相邻锚点之间 30%–45% 处的支撑窗， 取窗内角速度模长最小样本的中位数 较小的那个方向当脚掌俯仰正向（这就是 V4 换掉「只用三阶矩定符号」的地方； 两个方向都没有支撑样本、或分数完全相同时才退回三阶矩）。俯仰角速度代理 p 定下来后，对 p 的正值做两类间方差最大化定摆动门限 T， 相邻锚点之间在 30%–45% 处取加速度模长最小的点为中间支撑，往前找第一次正→非正得 IC（首次触地候选）， 往后找最后一次非正→正得 TO（离地候选），各取该区间内 p 的谷值。

除逐段内部搜索外还有三处补充，事件表「来源」列会写清楚：首端 TO / 末端 IC（记录最外侧有效片段， 借最近一次摆动当参考周期）、弱起步（首强摆动之前若还有一次同时超过前缀 p 与 |ω| 局部 Otsu 门限的弱摆动， 能配出完整一对才补，最多补一对）。这三种是独立候选、需视频确认；图上画成淡线 + 顶端空心点， 内部分段是实线 + 色块。一次成功分段成对输出，所以 IC 与 TO 数量相等不等于每一步都检到了。

边界：轴选择、门限、方向、锚点抑制都吃整段历史，非因果，不给实时时延保证；传感器须固定在脚背， 安装旋转或动作类型改变会让「方差最大轴 = 脚掌俯仰」这条假设失效。时间映射缺失、包序号倒退或跳号、时间倒退都会切开可分析片段， 被切开的周期连同拒绝原因一起进「分段 CSV」。维特 TXT 没有包序号、时间轴又是上位机写盘批次重建的， IC / TO 只作参考候选，别和 parquet 的结果同等看待。真实落步时刻仍需视频或独立参考标注核对。

数据来源与 raw / physical 的关系

同一帧里 IMU 有两份并列的数：imu_physical_values 是采集端换算后的物理量（前 3 个加速度 g、后 3 个角速度 °/s， axis_order_code = ax_ay_az_gx_gy_gz，accel_unit_code = g、gyro_unit_code = deg_per_s）； imu_raw_values 是同一帧的硬件整数计数（LSB，无量纲）。两者不是简单乘一个系数：加速度的刻度随量程变 （本批数据存在 1/4096 与 1/2048 g/LSB 两种），角速度恒 0.07 °/s 每 LSB；而且 raw 的通道序与物理轴相差一次置换与变号， 实测 Xphys = k·r2、Yphys = −k·r1、Zphys = k·r3（角速度同理：X = 0.07·r5、Y = −0.07·r4、Z = 0.07·r6）。 所以 raw 模式按原始通道序标 r1..r6（加速度 r1–r3、角速度 r4–r6），不冒充 X/Y/Z——同一时刻两模式的曲线形状因此可能看起来是「转过的」。 imu_raw_bits 在本批文件里整列为空；imu_unit_status 除 confirmed 外还有 partial， 这类帧的加速度三轴在 physical 里是空值（页面按缺值断笔）、raw 里仍有数，切到 raw 能连上看。

温度：同一帧还带一个设备温度，新版导出叫 gyro_temperature_celsius（0.01 ℃ 量化， 网页 1.x 导出用的是同一个量、列名 temperature_c，两个名字都认），维特 TXT 取「温度(°C)」列。 有就画在六轴下面那条窄带里，纵轴按全段 min–max 定 —— 温度都是正值，按 ±最大值居中会把它压成一条直线， 看不出冷却或自热。没有这一列的导出（62 列的老文件）不画这条带，顶栏也不出温度 chip。

推断方法与它的边界

三步都只用这份 IMU 自己的数据，不查厂商坐标先验：① 垂直轴——找加速度模长稳定的静止段（站立 / 深蹲时脚不转），把静止时的加速度方向当作重力反方向； ② 内外侧轴——扣掉零偏后，在重力系里对行走段角速度做 PCA，第一主成分就是内外侧轴（行走时主要绕它转），符号不定 （零偏取「角速度稳」的静止帧逐轴中位数：行走支撑相脚不移动，但踝在滚动，陀螺有 10–30 °/s 的常值电平，整体取中位数会把支撑相电平当成零偏）； ③ 前向符号——三项独立判据投票：相邻支撑中点之间的双积分位移（步幅）、支撑末到支撑初的双积分位移（摆动）、以及「若 z 轴是脚背外法线则其水平投影朝脚尖」的几何关系。 三项都同向才判「高」。
边界：没有行走段就没有前向符号（纯深蹲数据只能给出垂直轴与内外侧轴）；双积分要求采样率够高、零偏够小，采样率低或零偏大时位移会被低估，前向只能到「中」； 几何判据要求 z 轴与重力夹角在 15°–75° 之间，z 轴几乎水平或几乎垂直时该项自动失效；倒走会让双积分两项整体反向。
本页只认 imu_physical_values：imu_raw_values 的通道序与物理轴相差一次置换与变号，不是解剖轴，推出来的「x/y/z」没有意义。
左右脚并排显示，各一张三维轴投影：灰=解剖轴（前 / 左 / 上），彩=传感器 x / y / z。拖动旋转视角（两脚共用同一视角，便于对照）、滚轮缩放、双击复位；PNG 导出的是当前视角。三项判据各自的偏角写在下方「判据明细」里。
参考数据（工具栏右侧）：同一次录制里另一台设备、或另一只脚的文件可以一起拖进来（一次拖两个文件，第二个即参考），也可以点「选择文件」单独选。 两份数据贴的部位不同、坐标系不同，轴向结论不能互相搬；能搬的只有两件事 —— 落地冲击的时刻和贴地时加速度完全静止。 前者是瞬时事件，两边撞在同一时刻几乎不可能，所以用各自最强的那次冲击配对来对齐时间戳（录一段标定动作时故意跳一次最省事）； 后者用来切出动作段，再逐段单独推断。这一步是必要的：全段一次做 PCA，只要掺进一段转身，绕垂直轴的能量就会压倒前后摆动，内外侧轴直接定不出来 —— 分段之后每段各自干净。 表格里点任意一行，就把那一段的结果换成上面的详情；点「✕」清除参考数据。

方法与边界

只用六轴：陀螺积分跟踪姿态，加速度只在合量接近 1 g 时用来纠正倾角，相减后得到竖直加速度。 分段取竖直速度过零处为转向点（顶端、底端），每段在这两点强制速度为零后重新积分，深度即该段位移 —— 除了「转向点竖直速度为零」不再有任何外部参考。
可信度分三档：时长与节奏最稳；峰速约 ±0.15 m/s；深度受姿态残差影响，下蹲与起身是两次独立估计，「一致性」列就是两者相对差，超过 35% 的行会压暗，此时不要按精确位移使用。 底部加速度不经过积分，是这一页最稳的量，但它是传感器测到的加速度，不是关节冲击力或地面反作用力。
采样率约 50 Hz 时只能看缓变的蹲起过程，抓不住很窄的冲击峰；时间轴是上位机写盘重建的时刻，不是硬件采样时刻。 本页面向离散动作（深蹲、硬拉、起立）；连续步行会被切成大量「动作」，不要按单次动作解读。设备装在腕上时测的是手腕运动，叉腰或握杠时才可以近似当作身体升降，徒手自由摆臂不成立。

数值为 parquet 里 pressure_values 的原始读数，即 12 bit ADC 计数（0–4095），未换算成力或称重、未做基线扣除、未平滑。灰色「全 0」表示该通道全段没有任何非零读数。IMU 页可在两份并列数据间切换：imu_physical_values（采集端已换算，加速度 3 轴 g、角速度 3 轴 °/s）与 imu_raw_values（硬件整数计数 LSB，通道序 r1–r6，与物理轴相差一次置换与变号），与压力同帧同序，均未做任何滤波。角速度按帧取口径：该帧带扣偏结果（imuCalibration.status = ready）就用扣偏后的值，没有才用采集端换算的原始值；顶栏「角速度」一项会标出两种各占多少帧。原始值本身不被改写，仍在 angularVelocityRaw 与本列里。IMU 页可切「连线 / 点」两种画法；「丢帧标记」把相邻两帧时间差超过阈值的区段铺淡红底、栏顶加一道红杠，阈值默认 40 ms（50 Hz 下一个标称周期 20 ms，超过它就是至少丢了一帧）。维特 TXT 也能用这个标记，阈值默认 100 ms —— 它的时间轴是按写盘批次重建的，逐帧间隔是重建产物，填 40 会把写盘节奏的抖动标满屏；这类文件的真实缺口看「丢包 / 采样率」页。波形图与 IMU 共用同一个时间窗：在任一页框选 / 缩放 / 平移，另一页跟着走；轴向推断页选「当前时间窗」时只吃窗口内的帧。时间窗条显示在波形、IMU 与轴向推断页，起止秒数可直接输入（只填一头时另一头保持当前跨度，回车生效）；波形页的缩略条画全段负荷（每 0.5 s 一个桶，取该桶内「56 通道读数之和」的峰值，按全段最大值开方定高），拖两端改跨度、拖中间平移、空白处拖动框选、单击跳到该时刻、滚轮以指针为中心缩放。帧数超过 3 万的录制只把当前窗口读进内存，缩略条与零值率等全段统计由后台顺序扫描补齐，扫描完成前缩略条右侧压一层淡底并标「统计中」，越界部分不要当成真的没有数据。各页 PNG 导出的是当前视图，CSV 只导出当前时间窗内的帧。文件带温度列（gyro_temperature_celsius / temperature_c / 维特「温度(°C)」）时，IMU 页在六轴下面多一条温度带，纵轴按全段 min–max 定，悬停读数与 IMU CSV 导出也一并带上温度；没有温度列就不画。
维特 TXT（WT901 / JY901 上位机导出）只有 IMU：压力三页不可用，IMU、丢包与轴向推断三页照常。纯 IMU 的 parquet（pressure_status = not_applicable，每帧 pressure_values 是空列表）同理：压力三页禁用、默认落在 IMU 页，时间戳仍是设备硬件时刻，丢帧阈值照用 40 ms；少数没映射到会话时间轴的帧会被丢掉并在顶栏标出数量。这类文件按设备名称分列，侧别取 MAC 尾两段；时间戳只到毫秒、同一毫秒里常压着多帧，所以时间轴是把同一时间戳的帧均匀摊开、再按平均间隔定采样率。这类文件的时间戳是上位机写盘时刻而不是采样时刻（实测 40 帧挤在 16 ms 内写完），逐帧间隔不能当丢包，丢包页因此改按累计帧数估：局部帧率取 ±3 s 窗的回归斜率，整段缺口按名义 50 Hz 折算，分辨率约 0.2%。
